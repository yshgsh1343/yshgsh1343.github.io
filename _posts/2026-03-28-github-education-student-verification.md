## 前言

这两年 GitHub Education 的学生认证明显收紧，甚至真学生也会遇到过不了认证的情况。国内直连 GitHub 本来就容易抽风，而认证流程又会要求浏览器共享地理位置、调用摄像头、上传学生材料。用校园网网页可能刷不出来，用代理又容易造成 IP、地理位置和学校信息互相打架，最后就变成真学生也要反复排查环境和材料。

这篇不是教人伪造身份，也不是教人绕过审核。前提很简单：你本来就是在读学生，只是 GitHub 的自动审核没有正确识别你。下面记录的是我当时整理出来的排查思路。

## 准备工作

1. 学校邮箱，最好是学校官方域名邮箱。
2. 能稳定访问 GitHub 的浏览器。国内环境下可以优先尝试浏览器自带的安全 DNS / DoH，目标是尽量不用代理也能打开 GitHub。
3. GitHub 账号的实名资料、邮箱和 2FA。
4. 官方学生材料，比如在读证明、学籍报告、学校系统导出的证明文件等。材料要真实、当前有效、可读性足够好。
5. 一个清晰可用的摄像头环境。笔记本摄像头太糊、对焦太差时，可以换外接摄像头或手机摄像头，但材料本身必须是真实的。

## 注意事项

- 申请过程中尽量保持网络环境稳定，不要反复开关 VPN / 代理。
- GitHub 账号里的姓名、学校邮箱、学生材料上的信息要能互相对应。
- 2FA 不要省略，认证流程里经常会被要求。
- 如果你确实是远程学习、交换学习或不在学校所在地，最好准备能说明当前学习形式的官方材料，而不是临时编一个解释。
- 上传材料时不要改动证明内容。可以做的是提高扫描/拍摄清晰度、裁掉无关边框、使用官方英文版或官方可验证报告；不要把材料改成它本来不是的样子。

## 步骤

### 1. 先把 GitHub 访问环境稳定下来

认证前先确认 GitHub 本身能稳定打开。我的经验是，浏览器的安全 DNS 有时能缓解国内直连 GitHub 时的解析问题。以 Brave / Chrome 为例，可以在「隐私与安全」里打开安全 DNS，换成 Cloudflare、Google 或其他可靠的 DoH 提供商。

如果 Chrome 提示「浏览器由贵单位管理」导致相关选项不能修改，可以检查是不是系统策略里残留了 Chrome 的管理项。很多时候这是旧软件或安全工具留下的策略，不一定真的是学校或公司在管理浏览器。

这一步的目的只是让浏览器能稳定访问 GitHub，并不建议在认证过程中一会儿代理、一会儿直连。审核系统最怕的就是账号资料、IP、定位、学校信息互相不一致。

### 2. 补全 GitHub 个人信息

GitHub Education 会综合看账号信息、邮箱、学校、材料和当前申请环境。认证前建议先检查：

- Profile 里的姓名是否和学生材料能对应；
- 邮箱里是否已经绑定学校邮箱；
- 账单信息或地区信息是否明显和实际情况冲突；
- 账号是否已经开启 2FA。

我一开始也容易忽略 Profile 这类看起来不重要的地方，但认证类产品通常就是会用这些细节做交叉验证。真学生被误杀，很多时候不是单点材料不合格，而是多个信息源之间看起来“不像同一个人”。

### 3. 绑定学校邮箱并开启 2FA

如果注册 GitHub 时就用了 edu / edu.cn 学校邮箱，这一步会省很多事。否则建议先去 GitHub 邮箱设置里绑定并验证学校邮箱。

2FA 也尽早开好。安卓可以用 Authenticator 类应用扫码，苹果系统自带密码/验证码管理也能处理。开完之后记得保存 recovery code，不然后面手机丢了会很麻烦。

### 4. 开始申请 GitHub Education

进入 GitHub Education 的学生认证入口后，如果学校邮箱已经绑定成功，有时学校会直接出现在可选列表里。能选到学校时，尽量使用系统识别出的学校项，不要手动输入一个相似但不完全一致的名字。

浏览器请求定位权限时，尽量使用和自己真实情况一致的网络环境。如果你在学校所在地，那就用学校网络或稳定的本地网络。如果你不在学校所在地，例如远程学习、假期回家、交换项目等，就准备能解释学习形式的官方材料。不要为了让页面通过而临时制造一个和事实不一致的位置。

### 5. 上传学生材料

材料的重点不是“看起来像”，而是 GitHub 能不能从中读出几个关键事实：

- 你的姓名；
- 学校名称；
- 当前在读状态；
- 有效期或能证明当前仍在读的时间信息；
- 如果是远程学习、交换学习或其他非传统在校状态，材料里最好有对应说明。

国内学生可以优先考虑学信网的学籍/在读相关报告，或者学校官方系统导出的证明。如果 GitHub 对中文材料识别不好，可以使用官方英文版、官方翻译件，或让学校开具英文证明。

有些材料不是内容不合格，而是拍得太糊、字体太小、边缘反光、关键信息被遮住，导致 OCR 识别失败。这个时候应该重新扫描、重新拍摄、提高分辨率，而不是修改材料内容。

### 6. 如果被拒，先排查一致性

真学生被误杀后，最容易急着连续重试。但我的建议是先停下来检查几类一致性问题：

- GitHub 账号姓名和材料姓名是否能对应；
- 学校邮箱是否已经验证；
- 学校名称是否选错了校区、学院或相似学校；
- 当前网络/IP/定位是否和材料解释互相矛盾；
- 材料是否过期、模糊、缺少在读状态；
- 是否开了代理后又共享本地定位，导致审核侧看到的信息互相冲突。

如果这些都没问题，可以走 GitHub Support 或 Education 的申诉路径，说明自己是真实在读学生，并补充更清晰、更官方的材料。相比反复提交同一份模糊材料，申诉和补充说明通常更靠谱。
